1. Marksheet source

Paste the ordinary share link — a Google Sheet, a Google Drive Excel/CSV file, Dropbox, GitHub, or OneDrive/SharePoint are all recognised automatically, no special “publish” step needed. The file just needs to be shared as “Anyone with the link can view.” Save the link once and hit Refresh after each update, or use Upload if you'd rather pick a file each time. The half-semester and final reports each remember their own source.

2. Assessment columns detected

These were pulled straight from your marksheet's own column headers and (where available) its own maximum-marks row — nothing here was typed from scratch. Where your sheet has its own weighted percentage next to a raw mark column (common in CLO-based templates), that weight is picked up automatically too, so a component graded out of 100 but worth 40% of the grade doesn't get treated as equal to one worth 10%. Skim it, fix anything that guessed wrong, then the report below is ready.

4. Hexagon competency mapping

Maps your assessments onto six competency axes for the student dashboard (separate from ViTrox LMS's official release) — Teamwork, Knowledge, Problem Solving, Critical Thinking, Attitude, and Numeracy. Tag each assessment below; some need a question-mix split since a single quiz can touch more than one axis.

What to have ready before you start (checklist)

Per assessment (once each, applies to every student):

  • Confirm the type — Quiz/Test (Numeracy only) or Assignment/Other (all tags available)
  • Question mix % — either your own estimate, or the actual question paper (PDF/photo) so Claude can read and suggest it

Per student (the harder-to-source data):

  • Consultation hours — a sign-in log, calendar, or your own record of who attended
  • Plagiarism % — a Turnitin/similarity score, if you use one (leave blank if you don't)
  • Careless-mistake % — review the student's marked script yourself, have the scanned answer script ready for Claude to read, or just type your own perception in plain language and let Claude estimate it

If using AI to help with any of the above:

  • Your own AI API key (pasted in once per session, never saved)
  • Scanned question papers, one per assessment
  • Scanned answer scripts, one per student per assessment — name files so the Student ID appears (e.g. DCS2606019_Quiz1.pdf) so they auto-match

Everything above is optional — if a piece of data is missing, that axis just shows "—" for that student instead of a wrong number. You don't need all of this ready on day one.

Assessment Counts toward Question mix % — Concept / Direct application / Indirect application

Per-student inputs — consultation hours (ideal: 4/semester), plagiarism % (from Turnitin or similar, if used), and, for Numeracy, roughly what share of marks lost on each assessment came down to careless mistakes rather than a real gap in understanding. The last two columns let you type your own read on a student in plain language and have Claude suggest numbers for the columns above — reusing the same API key as the AI-assisted analysis below.

7. Conclude Course

Once the student has sat their final examination and the result is released, use this to archive a permanent End of Semester record for every student and lock the live coursework report - from then on, students see this under a new "Archived" tab on their dashboard instead of "End of Semester." You can run this again later (e.g. to refresh the archived snapshot after a correction) - it always reflects whatever's currently loaded here. To undo (e.g. if this was clicked by mistake), use the ordinary Publish button above afterward - that always overwrites the live report with current data again.

8. Game Questions (Impian Quest)

Students earn one game wish per correct answer. Write multiple-choice questions for this subject here, then press Publish game questions & enrol students. That records which students take this subject in this semester, and every student is then only ever asked questions from the subjects they are enrolled in for the current semester (set that under Settings). Publishing here is separate from publishing marks - no results are touched. Each question pays a student only once and a wrong answer locks it for 24 hours, so aim for plenty (30+). A student enrolled in no subject that has questions gets a small, daily-capped General Maths practice instead. Note: answer keys travel to the student's browser with the questions, as with any app without a server, so treat this as a motivation tool rather than an assessment.

AI drafts appear in the form above for you to check - always verify the maths before adding. Uses the AI key from step 3, the topics in scope, your notes (if any), and avoids repeating questions you already have.

7. Consultation Scheduling

Syncs your real Google Calendar into a sanitized snapshot students can see, so they can request a consultation slot — the request is written to Firestore, not your calendar. You still book it yourself, for real, afterwards. Not live/real-time: it's exactly what your calendar looked like the moment you last clicked Sync, same as Publish.

This needs a one-time Google Calendar API setup (reuses the same Google Cloud project as the email feature) and, if you want the Chat notification, a Google Chat webhook.

Two independent weekly caps, both enforced at once: your own total across every student combined (once your synced calendar shows this many "Consultation:" hours for a week, no one gets any more slots for it) and a per-student limit (stops any single student from booking more than that many hours within a week, across however many separate requests they submit). Both are shown to students and enforced when they try to book. Both webhooks post a notification on submit, approve, and decline. Fired directly from the student's browser, best-effort — delivery isn't guaranteed from here, so test each one and confirm it actually arrives. There's no way for this app to send an email "from your Gmail" itself when a student books, since that would need your own sign-in at a moment you're not present - the email-me field is instead meant to point at a free automation service (Zapier, Make.com, IFTTT) that receives this webhook and sends the actual email from your connected account on its own side, entirely outside this app. Approving or declining is different, though - that action runs in your own browser, so if you've connected Gmail (in the Report tab's email step), the student gets a short email straight from your account confirming the outcome and your remark, sent to the email already on their request — no marksheet needs to be loaded for this. The holiday calendar is a public Google calendar ID (defaults to Malaysia's official public holidays) — synced alongside your own calendar so no slot is ever offered on a public holiday; clear the field to turn this off. The "how students should reach you" field is shown to students right where they're told to contact you directly for a time outside what's offered — an email address becomes a clickable mailto: link automatically, a Chat/Meet/WhatsApp link becomes clickable too, or just type free-form instructions (e.g. "message me on Teams"). This is separate from the webhooks above on purpose: those only notify you, they can't be a link students click, since exposing that URL would let anyone post messages into your Chat space as you.

Only while this browser tab is actually open and running — there's no server behind this app, so it can't sync in the background if the tab is closed or the computer is asleep. Needs one manual sync first (above) to get started; if left running past about an hour, the underlying Google authorization may expire and it'll stop itself with a message asking you to sync manually again.
