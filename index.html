Once connected, every add/edit/remove writes straight to Firestore in real time, and every browser pointed at the same config sees the same live data. This screen only appears after you sign in with an admin account — but that sign-in only protects the app's own screens. Bulk add, replace, or delete results

For entering a batch of new results, or correcting/removing many at once. Export the current intake to edit in Excel (each row keeps its Record ID), or start from a blank template for pure new entries. Editing a row and re-uploading replaces it; marking a row "Delete? Yes" removes it; a row with no Record ID is added as new. Nothing is applied until you confirm what the file will do.

Firestore security rules

This is what actually protects the data — the sign-in screen alone does not. Paste this into Firebase Console → Firestore Database → Rules and click Publish, before you put any real student data in. Safe to leave visible here — these rules aren't a secret, they're what enforces that only a signed-in admin account can read or write anything.

Subject code & credit-hour changes

If a curriculum revision renamed a subject's code or changed its credit hours, upload the change here instead of editing existing results. This never rewrites a stored record — it only tells the app "treat X as Y" when it computes GPA/CGPA and matches retakes, so what's on file stays exactly as entered, and removing a mapping instantly reverts every calculation that used it.
